# Nivasa

Student-first hostel and PG discovery for Pune and the wider Pune Metropolitan Region.

A student enters where they study, a monthly budget, how they travel, what they eat and what they
cannot do without. Nivasa ranks stays against those preferences on a real map and explains each
result: what it will really cost per month, how long the commute takes, and where the nearest
suitable mess, pharmacy and xerox shop are.

```
Student inputs → validation → matching (FastAPI) → Pune map and ranked results → listing detail → contact / visit / save / compare
```

## What is real and what is not

| Data | Status |
| --- | --- |
| Colleges (36) | Real. Coordinates from OpenStreetMap objects, each with its `osm_ref`. Colleges without a reliable OSM entry (for example PICT) are left out; students can pin them on the map. |
| Pune Metro | Real. Purple and Aqua line stop order from OSM route relations; under-construction stations shown but not routed. |
| Shops, messes, police, hospitals and clinics | Real OSM snapshot, with each place's phone, email, website, address and opening hours where OSM has them. Click any place on a map (or in a listing's nearby lists) for its details card. Coverage of small shops and messes is incomplete. |
| Major hospital contacts | Hand-checked on 2026-10-18 (`backend/app/seed/data/hospital_contacts.json`): Ruby Hall, Jehangir, Deenanath Mangeshkar, KEM, Aditya Birla, Poona Hospital, Manipal, Jupiter from their official sites; Sassoon, Sahyadri, Noble from public directories (labelled as such). |
| Real hostels and PGs | Every named hostel, PG and student residence mapped on OSM (`osm_stays.json`), as listings with ids `osm-…`. Contacts as mapped; rent, rooms and rules are unknown and shown as such. Campus hostels are flagged. |
| Map tiles, address search | OpenStreetMap tiles and Nominatim (configurable). |
| Listings (83) | **Demo data.** Fictional, generated by `scripts/generate_demo_listings.py`, flagged `is_demo` and labelled "Demo" everywhere. No contact details, ratings or reviews. |
| Commute times and costs | Estimates from documented fares and speeds ([docs/METHODOLOGY.md](docs/METHODOLOGY.md)). |

Real listings enter through **Add a listing** (`POST /api/submissions`), stay hidden as `pending`
and appear only after an admin approves them.

## Stack

- **Frontend:** React 19, TypeScript (strict), Vite 8, Tailwind CSS 4, Leaflet + React Leaflet, React Router, Lucide icons. Tests with Vitest and Testing Library.
- **Backend:** Python 3.11+, FastAPI, Pydantic 2, SQLAlchemy 2, Alembic, SQLite locally (any SQLAlchemy URL, e.g. Postgres, via `NIVASA_DATABASE_URL`). Tests with pytest; lint with ruff.

```
backend/
  app/
    api.py              HTTP routes under /api
    models.py           SQLAlchemy models (listings, rooms, OSM places, metro, reports)
    schemas.py          Pydantic request/response models and validation
    services/           geo index, metro network, commute, matching, search, geocoding, routing
    seed/               loader (python -m app.seed) and data snapshots
  alembic/              migrations
  tests/                pytest suite
frontend/src/
  pages/                search form, results + map, listing, saved, compare, add listing, how it works
  components/           preference form, destination picker, Leaflet map, cards, detail sections
  lib/                  API client, types, URL preferences, local storage
scripts/
  fetch_osm_data.py     refresh the OpenStreetMap snapshot (stdlib only; `pois stays` to fetch just those)
  generate_demo_listings.py
docs/METHODOLOGY.md     scoring, commute and cost rules with sources
```

## Run it locally

Prerequisites: Python 3.11+ and Node 20+.

```bash
cd backend
python -m venv .venv
.venv/Scripts/activate        # macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload --port 8000
```

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open http://127.0.0.1:5173. API docs are at http://127.0.0.1:8000/api/docs.

## Checks

```bash
cd backend && pytest && ruff check .
cd frontend && npm run typecheck && npm run lint && npm test && npm run build
```

## API overview

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health`, `/api/meta` | status; labels, defaults and dataset attribution |
| GET | `/api/colleges` | destinations with OSM references |
| GET | `/api/transit` | metro lines and stations |
| GET | `/api/pois?south&west&north&east&categories` | mapped places in a small bounding box |
| GET | `/api/geocode?q=` | colleges by name, then Nominatim within the Pune region |
| POST | `/api/search` | preferences → ranked, explained results plus hidden counts |
| GET | `/api/listings/{id}` | listing facts |
| POST | `/api/listings/{id}/match` | one listing scored against preferences |
| POST | `/api/listings/{id}/reports` | report wrong or outdated information |
| POST | `/api/submissions` | suggest a listing (stored as pending) |
| GET/POST | `/api/admin/submissions[/{id}/approve\|reject]` | review queue; requires `X-Admin-Key` and `NIVASA_ADMIN_API_KEY` |

## Configuration

See `backend/.env.example` and `frontend/.env.example`. Notable settings:

- `NIVASA_INCLUDE_DEMO_LISTINGS=false` hides demo data once real listings exist.
- `NIVASA_ROUTING_PROVIDER=osrm` uses OSRM road distances (falls back to the estimate on failure).
- `NIVASA_GEOCODER=none` disables Nominatim; set `NIVASA_NOMINATIM_USER_AGENT` with real contact details before public use.
- `VITE_TILE_URL` must point at a production tile provider before launch: OpenStreetMap's own tile servers do not allow heavy traffic.

## Refreshing data

```bash
python scripts/fetch_osm_data.py           # new OSM snapshot into backend/app/seed/data/
python scripts/generate_demo_listings.py   # regenerate demo listings
cd backend && python -m app.seed           # reload; real (non-demo) listings are kept
```

## Deploying

The backend is a standard ASGI app (`uvicorn app.main:app`); run `alembic upgrade head` and
`python -m app.seed` on release. The frontend builds to static files in `frontend/dist/`; serve
them with any static host, routing unknown paths to `index.html`, and either proxy `/api` to the
backend or set `VITE_API_BASE_URL` at build time and add the site to `NIVASA_CORS_ORIGINS`.

## Known limitations

- No verified real listings yet; all listings are demo data.
- Commute times are estimates, not live timetables or traffic.
- OSM coverage of messes (45 mapped) and small shops is thin, so food and market scores lean on what is mapped.
- No accounts: saved stays and comparisons live in the browser's local storage.
